# V3 — refonte visuelle et mécaniques

## Version et préservation

Entrée nouvelle : `v3/index.html`. `current/index.html` reste la V2.1 stabilisée, intégralement inchangée. Les V1, V2 et sauvegardes restent dans `versions/`. Le tag Git local `v2.1-stable` conserve le point de départ. La V3 garde la boucle, les fonctions physiques et les menus du moteur ; le personnage, le décor et le générateur passent par des modules externes ciblés. Aucun backend Supabase, portail, code de récompense ou connexion Lightspeed n'a été ajouté.

## Jacques

Un véritable atlas PNG transparent original remplace le personnage dessiné en rectangles. Il a été généré à partir de la maquette puis affiné avec la photo individuelle reçue pendant la réalisation : crâne chauve, visage, chemise noire, pantalon rouille, chaussures foncées et tatouage. La ressemblance artistique reste à confirmer par le propriétaire ; aucun modèle RONA n'a été copié.

L'atlas compte 24 cellules, dont 23 utilisées : 6 course, 2 idle, 4 premier saut, 4 double saut, 2 descente, 2 atterrissage, 3 collision ; la dernière pose est conservée en réserve. Les comptes ne sont pas les nombres indicatifs du cahier des charges. `v3/assets/jacques-atlas.json` pilote séquences, cadences et boucles. `v3/jacques.js` utilise les rectangles complets renseignés dans le JSON, isole les silhouettes alpha en cache pour éviter les fragments voisins et applique une échelle commune, sans lissage, pieds alignés sur le sol. Les poses ramassées gardent leurs proportions. Le corps de collision reste un rectangle intérieur 32×72 avec marge 5 px ; les bras/jambes débordant du corps ne provoquent pas de collision. La silhouette debout mesure environ 80 px.

L'atlas est une ressource originale générée, pas une animation finalisée manuellement par un pixel artist. La qualité visuelle est visible dans le vrai jeu ; retouches de continuité ou de ressemblance peuvent encore être nécessaires après revue. Le chargement défaillant bloque le lancement avec un message et Réessayer ; aucun personnage approximatif de substitution.

## Forêt

Panorama original détaillé : aurores, étoiles, montagnes, pins, lac et cabanes éclairées. Des plans supplémentaires rasterisés et mis en cache déplacent conifères, reflets, sous-bois, oiseaux, chevreuil, écureuil, hibou, sentier et fougères à différentes vitesses. Voir `SCENERY-V3.md`. Neuf groupes de rendu exposent leurs facteurs de parallaxe. Le panorama contient plusieurs plans artistiques déjà composés ; montagnes et ciel ne sont pas neuf PNG séparés. Le parallaxe réel provient des plans animés superposés et du léger déplacement du panorama.

Le même décor et le même personnage sont dessinés pendant la partie et dans les menus. Palette boréale, crème et rose pour les interfaces. Aucune référence Firebarns dans la V3. La police officielle n'est pas fournie : repli système, aucun fichier de police sans licence.

## Mécaniques et vérification

315 px/s au départ au lieu de 240 (+31,25 %), plafond 530. Double saut et règles de pointage conservés. Obstacles isolés et espacés selon la vitesse maximale ; troncs hauts nécessitant deux sauts et branches à éviter en courant dessous. Placement des collectibles tenant compte des dangers. Voir `MECHANICS-V3.md` pour les dimensions, trajectoires testées et limites de preuve.

`node tests/mechanics-v3.cjs` : 740 assertions. `node tests/v3-browser.cjs` : scénarios Chromium, sprites et états, physique, UI, erreurs d'assets, portrait/compact/paysage, captures du vrai Canvas. Rapport exact `artifacts/v3/results.json` et `TESTS-V3.md`. Les PNG représentent actuellement environ 10,55 Mio : le chargement initial sur connexion mobile lente devra être mesuré et les assets optimisés avant diffusion à grande échelle. Aucun test Safari/iOS ou téléphone physique exécuté. Les trajectoires automatiques de test prouvent une possibilité de franchissement pour les cas couverts, pas la facilité de jeu pour tous les joueurs.

## Utilisation et distribution

Depuis `/workspace/minijeux` : `npm ci --ignore-scripts`, puis `npm run dev`. Le serveur local sert `/v3/index.html`, sans build ni variable secrète. `npm run test:v3` lance la simulation et Playwright ; `npm test` conserve la vérification V2.1. Python 3 et Chromium installé nécessaires au runner.

`dist/defi-boreal-v3-jouable.zip` : index.html, modules et assets à la racine, déployables sur Netlify/hébergement statique. `dist/defi-boreal-v3-projet.zip` : projet, anciennes versions, documentation, tests, captures. Aucun node_modules, secret ou backend. Recréer les archives avec `python3 scripts/package-v3.py`. Aucun déploiement public effectué. Ouvrir via serveur HTTP pour le JSON d'animation ; double-clic file:// ne constitue pas le mode de lancement supporté.
